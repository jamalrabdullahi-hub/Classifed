0. READ FIRST — HOW THIS REPO WORKS (learned the hard way)
===============================================================================

- Package manager: pnpm workspaces + Turborepo. IMPORTANT: `run_command`'s cwd is
  NOT the project root here, so ALWAYS pass -C, e.g.:
      pnpm -C C:\FLTCrypto --filter @flt/core test
      pnpm -C C:\FLTCrypto --filter @flt/core typecheck
      pnpm -C C:\FLTCrypto --filter @flt/core exec vitest run --exclude "**/integration/**"
  A bare `pnpm --filter ...` resolves the workspace from the home dir and fails
  (and can trigger an install in the home dir). The integration tests need a DB
  and will HANG without one — always exclude "**/integration/**".

- No local Postgres. Prisma is MOCKED in tests. Migrations are HAND-WRITTEN
  (never `prisma migrate dev`). After editing schema.prisma run:
      pnpm -C C:\FLTCrypto --filter @flt/db exec prisma validate
      pnpm -C C:\FLTCrypto --filter @flt/db exec prisma generate
  A migration you write CANNOT be run/diffed locally — walk concrete rows through
  any CHECK by hand.

- i18n: every user-facing string needs an entry in BOTH
      apps/web/messages/en.json AND apps/web/messages/so.json
  (Somali). A missing key is a runtime failure. Somali here is best-effort and
  NEEDS NATIVE REVIEW (see §7).

- Layering: `@flt/core` defines ports; `@flt/providers` implements them. Core
  MUST NOT import providers. Provider code may import @flt/db. The worker may
  import both.

1. WHAT CHANGED, IN ONE PARAGRAPH
===============================================================================

FLT is now a custodian. Client funds pool in ONE FLT-controlled Privy wallet
("the omnibus"); the double-entry ledger is now the SOURCE OF TRUTH for
participant balances (buying power = ledger USER_AVAILABLE). Participants
deposit crypto (USDC/USDT) to their own FLT deposit address (swept into the
omnibus) or fiat (converted + credited), trade by FLT signing swaps from the
omnibus server-side, and withdraw by FLT sending from the omnibus. The chain is
consulted only to price assets, to hold (the omnibus), and to prove settlement.
This REVERSES ADR 0001 (non-custodial); that ADR is now marked superseded.

Everything is gated on CUSTODY_PROVIDER=privy and is a no-op when disabled, so
CUSTODY_PROVIDER=disabled still behaves exactly as before.

===============================================================================
2. DECISIONS MADE BY THE OPERATOR (do not re-litigate)
===============================================================================

- Deposit attribution: PER-USER deposit addresses (each participant's existing
  FLT/Privy wallet), swept to the omnibus. NOT a single shared address.
- The omnibus Privy wallet ALREADY EXISTS. It is supplied via env, not created.
- Depositing IS the authorisation to sweep (no separate WalletDelegation grant
  needed for sweeps).
- Only USDC and USDT are custodied.

5. KEY INVARIANTS (do not break)
===============================================================================

- Ledger sign convention: debits positive, credits negative, every transfer sums
  to zero (enforced by a DB trigger). Asset accounts >= 0, liabilities <= 0.
- Settle/credit/debit ONLY against a MINED receipt, never a broadcast.
- Every ledger movement is idempotent on (kind, reference). References used:
    crypto-deposit:<sweepTxHash>   trade-lock:<quoteId>   trade-unlock:<txId>
    trade-sell:<txId> trade-buy:<txId>   withdrawal:<id>
    withdrawal-lock:<id> withdrawal-unlock:<id>   fiat-convert-usd:<id> ...
- Move an amount available -> locked BEFORE broadcasting a trade or withdrawal,
  so the same balance cannot back two things.
- Settlement of a spot trade is TWO single-asset transfers (sell leg + buy leg).
  The participant is credited (received - fee); fee -> FEE_REVENUE.
- Reconciliation NEVER writes a ledger balance to match the chain. A shortfall
  (owed > held) is the failure. A surplus is expected (revenue sits in the
  omnibus when the fee recipient is the omnibus).
- The integrator fee recipient MUST be the omnibus (FLT_FEE_RECIPIENT_ADDRESS),
  or the omnibus holds less than the ledger credits it for — reconciliation will
  flag it. 0x always prices the fee in the BUY token (see zeroex.ts).

7. KNOWN GAPS / CAVEATS / FOLLOW-UPS
===============================================================================

- SOMALI TRANSLATION: new/changed strings in messages/so.json (nav.withdraw,
  the withdrawPage namespace, and the deposit-namespace edits) are best-effort
  and NEED NATIVE-SPEAKER REVIEW.
- CRYPTO-DEPOSIT SCREEN: not a dedicated screen. The participant's deposit
  address is shown on the existing wallets page (/boorso). A dedicated "send
  USDC to this address" screen is a possible follow-up.
- DEPOSIT DETECTION BACKFILL: apps/worker/src/custody.ts scans a fixed ~2000
  block window per pass. Fine live; not a backfill. A deployment starting after
  funds already sit at a deposit address needs a one-off backfill or a persisted
  per-chain cursor. Nothing is lost (funds stay on-chain).
- WITHDRAWAL BROADCAST FAILURE: a failed broadcast leaves the withdrawal PENDING
  to retry (not FAILED), so a persistent failure = a stuck row for an operator.
- ALERTING: reconciliation (and the worker generally) alerts via console.error +
  the worker result log. MAIL_PROVIDER=console means NO email delivers yet.
- MAIL: unchanged — MAIL_PROVIDER=console in prod (per HANDOFF).
- INTEGRATION TESTS: still none; the ledger/DB constraints are not exercised in
  tests (DB is mocked). The two new migrations were validated with `prisma
  validate` only, plus hand-walked CHECK examples.
- PERPS: NOT converted to custody (perps still use the old paths). Out of scope
  for this work.
- APPROVALS: the omnibus must be approved for each sell token's AllowanceHolder
  before the first swap in that token (the approvals route now does this from
  the omnibus on demand).
